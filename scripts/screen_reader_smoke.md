# Screen reader smoke test — دستی

> چک‌لیست برای NVDA روی Windows. این تنها چیزی است که ابزار خودکار
> نمی‌گیرد.

---

## چرا این فایل وجود دارد

سه ابزار خودکار داریم — `a11y_audit` (axe)، `contrast_audit` و
`map_audit` — و هر سه در CI اجرا می‌شوند. ولی **هر سه یک چیز را
نمی‌سنجند**: اینکه خروجی برای **گوش** چه معنایی دارد.

axe نبودِ نام را می‌گیرد، ولی **گیج‌کننده بودنِ** نامی که هست را نه.
آن دسته از مشکلات فقط با گوش پیدا می‌شود.

### یک تله که در نوشتن همین فایل خوردم

اولین اندازه‌گیری من نشان داد نام کارت‌ها چنین چیزی است:

```
«۰ مترببریگربهشیطون و بامزه۰ لحظه د»      ← این غلط بود
```

**این آرتیفکت سنجش من بود، نه باگ.** آن رشته از `textContent` می‌آمد
که برخلاف `innerText` بین عناصر جداکننده نمی‌گذارد. مرورگر برای نام
دسترس‌پذیری از `innerText` استفاده می‌کند، و همان اندازه‌گیری:

```
innerText    →  «۱۱ کیلومتر Rex سگ سگ وفادار و پرانرژی ۰ لحظه در دسترس»
textContent  →  «۱۱ کیلومترRexسگسگ وفادار و پرانرژی۰ لحظه در دسترس»
```

**فاصله‌ها سر جایشان هستند.** پس آن هشدار از این فایل برداشته شد.

این را نوشتم چون **دقیقاً همان کاری است که در این چک‌لیست از شما
می‌خواهم**: نتیجه‌گیری نکنید، اندازه بگیرید. من هم اول اشتباه کردم.

## نصف کار قبلاً خودکار سنجیده شده

قبل از شروع، این را بدانید تا وقت‌تان را روی چیزی که ابزار گرفته
تلف نکنید. `scripts/` اینها را تست می‌کند:

| سنجیده شده | ابزار |
|---|---|
| نبود کنتراست (۱۴۴ → ۰) | `contrast_audit.mjs` |
| نقش/نام گمشده در axe (۳۴۵ → ۰) | `a11y_audit.mjs` |
| marker نقشه: Tab، Enter، نام | `map_audit.mjs` |
| **صفر مورد بی‌نام در ۵ مسیر** (۲۱–۲۲ tab stop هر کدام) | `probe_taborder` |

پس این‌ها را **دوباره چک نکنید**. آنچه می‌ماند:

- آیا نامی که **هست** فهمیدنی است؟
- آیا ترتیب اعلام‌ها منطقی است؟
- حالت خالی و مودال چه می‌گویند؟
- و آنچه فقط با گوش فهمیده می‌شود

## آماده‌سازی (۲ دقیقه)

1. **NVDA** را نصب کنید (رایگان): <https://www.nvaccess.org/download/>
   اگر NVDA ندارید، این فایل `NOT_TESTED` می‌ماند — ولی روالش ثبت
   شده است.
2. سرور را بالا بیاورید:
   ```bash
   npm run audit:build && npm run audit:serve
   ```
   سپس در مرورگر: `http://127.0.0.1:4173`
3. برای صفحه‌های محافظت‌شده (`/me`)، اول با کاربر تست وارد شوید
   (`bk_12821` / `testpass123`).
4. در NVDA: `Insert+N` → Preferences → **Speech** → سرعت را روی
   `Rate 30` بگذارید. سرعت پیش‌فرض برای اولین بار گیج‌کننده است.
5. **گوش کنید، نه اینکه نگاه کنید.** اگر NVDA چیزی را مسخره خواند،
   همان لحظه **جملهٔ دقیقش** را یادداشت کنید — نه توصیفش.

## پنج مسیر

هر مسیر: `Ctrl+Home` بزنید، بعد فقط با `Tab` جلو بروید و
`Insert+Down` (خواندن پیوسته) را در جاهای مهم بزنید.

### ۱. خانه — `/`

| # | چک | چه چیزی درست است |
|---|---|---|
| ۱.۱ | اولین `Tab` | روی skip-link یا لوگو، با **نام** («پازمارکت — صفحه‌ی اصلی») |
| ۱.۲ | کارت آگهی | نام کارت یک **جملهٔ خوانا** است، نه قیمت+نام چسبیده |
| ۱.۳ | دکمهٔ قلب | «ذخیره‌ی آگهی» — نه «قلب» یا «دکمه» |
| ۱.۴ | `Insert+F5` (فهرست فرم‌ها) | هر دکمه نام دارد |

### ۲. کاوش — `/explore`

| # | چک | چه چیزی درست است |
|---|---|---|
| ۲.۱ | سوییچ لیست/نقشه | هر دو با نام، و **وضعیت فعال** اعلام شود |
| ۲.۲ | دکمهٔ فیلتر | «فیلترها» |
| ۲.۳ | کارت‌ها | مثل خانه: جملهٔ خوانا |
| ۲.۴ | تغییر لیست ↔ نقشه | NVDA تغییر را اعلام می‌کند (نه سکوت) |
| ۲.۵ | روی نقشه | markerها با **نام آگهی**، نه فقط «دکمه» |

### ۳. حیوانات — `/pets`

| # | چک | چه چیزی درست است |
|---|---|---|
| ۳.۱ | کارت‌ها | نام یک جملهٔ خوانا است، با مکث طبیعی بین بخش‌ها |
| ۳.۲ | badge گونه | «گربه» جدا خوانده شود، نه چسبیده به اسم |
| ۳.۳ | حالت خالی | اگر جستجو نتیجه نداشت: پیام **مثبت و راهنما**، نه سکوت |

> اندازه‌گیری `innerText` نشان داد نام این کارت‌ها درست جدا شده است
> (`«۱۱ کیلومتر Rex سگ سگ وفادار و پرانرژی ۰ لحظه در دسترس»`). پس اینجا
> دنبال **مشکل نام** نباشید — فقط ببینید مکث‌ها طبیعی‌اند یا نه.

### ۴. سرپرستی — `/adoption`

| # | چک | چه چیزی درست است |
|---|---|---|
| ۴.۱ | کارت‌ها | مثل `/pets` |
| ۴.۲ | دکمهٔ «درخواست سرپرستی» | نام درست **و** برای کدام حیوان معلوم باشد |
| ۴.۳ | **مودال درخواست** | روی باز شدن، NVDA **عنوان** را بخواند |
| ۴.۴ | داخل مودال | `Tab` داخل مودال بماند (خارج نشود) |
| ۴.۵ | بستن با `Escape` | فوکوس به **دکمه‌ای که بازش کرد** برگردد |
| ۴.۶ | فرم داخل مودال | خطاها با `role="alert"` اعلام شوند |

### ۵. حساب من — `/me`

| # | چک | چه چیزی درست است |
|---|---|---|
| ۵.۱ | هدر | نام کاربر + یوزرنیم خوانده شود |
| ۵.۲ | دکمهٔ «افزودن حیوان» | **یک** نام (نه «افزودن حیوان ستاره») |
| ۵.۳ | ستارهٔ الزامی | با `aria-hidden` — NVDA نباید «ستاره» بگوید |
| ۵.۴ | کارت‌های حیوان | مثل `/pets`: جملهٔ خوانا |
| ۵.۵ | **حالت خالی** | اگر حیوانی نیست: پیام راهنما خوانده شود |
| ۵.۶ | دکمهٔ خروج | «خروج» |

## سه چیز که در هر مسیر تکرار شود

### الف. ترتیب Tab

آیا ترتیب **چشم‌انداز** با ترتیب **خواندن** یکی است؟
در RTL، انتظار می‌رود از راست‌بالا شروع شود. اگر NVDA از
وسط صفحه شروع کرد، یک `tabindex` مثبت جایی هست.

### ب. نام‌های چسبیده

هر جا NVDA یک **کلمهٔ بلندِ بی‌معنا** خواند، آن یک باگ است.
جملهٔ دقیقش را بنویسید.

### ج. حالت خالی

هر لیستی که خالی می‌شود باید **بگوید** چرا. سکوت یعنی کاربر فکر
می‌کند صفحه خراب است.

## فرم گزارش

هر مورد را با یکی از این سه علامت بزنید و **جملهٔ دقیق NVDA** را
بنویسید:

```
✅  NVDA گفت: «...»
⚠️  NVDA گفت: «...»   ← مشکل: ...
❌  NVDA گفت: «...»   ← مشکل جدی
```

نمونهٔ یک گزارش خوب:

```
۳.۱  ✅  «۱۱ کیلومتر، Rex، سگ، سگ وفادار و پرانرژی، ۰ لحظه در دسترس»
         مکث‌ها طبیعی بودند.

۴.۳  ⚠️  «دیالوگ» — عنوان خوانده نشد
         مشکل: فوکوس روی اولین فیلد رفت، نه روی DialogTitle.
         انتظار: NVDA اول عنوان را بگوید بعد محتوا.
```

**عددی که نگرفتید را هم بنویسید.** اگر NVDA در دسترس نبود، همان
بالای گزارش بنویسید `NOT_TESTED — NVDA در دسترس نبود` و بقیه را
خالی بگذارید. این از گزارش حدسی بهتر است.

## بعد از تست

اگر موردی پیدا شد که **قابل خودکارسازی** است (مثل نام‌های چسبیده
که با خواندن متن از DOM سنجیدنی است)، به `scripts/` اضافه‌اش کنید
تا در CI بگیرد. الگوی این پروژه همین بوده:

> هر ابزاری که باگی پیدا کرد، به CI رفت.

| ابزار | باگ‌هایی که پیدا کرد |
|---|---|
| `a11y_audit` | ۳۴۵ مورد، و آن ۱۴۷ موردی که overlay پنهان کرده بود |
| `contrast_audit` | ۱۴۴ مورد، و بنر خانه با نسبت ۱.۱۹ |
| `map_audit` | دو باگ کیبورد در `MapView` |
| **`screen_reader_smoke`** | ← این فایل، هنوز صفر. پر کنیدش. |
